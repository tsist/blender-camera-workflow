# Blender 摄像机工作流

先读仓库中的插件使用说明和当前实现契约。当前保存事务面向官方 Windows Blender 5.2.1。运行环境须与该版本的包清单和校验条件相符。插件使用随包主机源码，从实际运行环境取得 Blender 和配套 Python 路径。其他 Blender 版本及 Linux 保存入口的可用性须按各自代码门禁和运行验证确认。

## 从观看目的确定镜头

从实际场景读取单位、帧率、画幅、主体、现有相机、动画区间、约束、外部依赖和已保存状态。需要用户决定的是观看意图、创作方向和可调整范围。能从场景或文件读取的信息直接检查。

先写清本镜让观众读到什么、何时获得新信息、哪些事件必须可见。将文字或参考图、分镜、视频转成可执行的镜头目标，记录采用的构图、观察方向、运动趋势、焦点或节奏。参考素材的角色、表演、布景和声音分别按任务授权处理。

明确的时间点使用实际场景帧率换算。对话同时考虑听者反应、手势和动作收势。记录表演事件、切镜、焦点到达和相机运动的时间关系。锁定的表演时点保持独立，摄影组改时需显式说明映射范围。

给少量可比较的方向，说明每个方向让什么更容易看清。方案已有明确选择时继续制作。需要改变已锁定的表演、资产或镜头意图时，先提出具体影响与用户选择。

## 组织可编辑工作副本

使用已保存源建立候选，记录源文件与 SHA-256、Scene、镜头身份、相机、请求和实现版本。每次新请求使用新的作业目录。GUI 未保存内容需先保存为明确工作快照，磁盘源与当前会话分别核对。

检查 Camera Object、Camera Data、Action、父级、路径、约束、驱动、NLA 和共享使用者。静态属性会影响使用该相机或数据的全部帧。动画和时间局部修改应选择对应的动态入口。门禁拒绝的关系保留原数据，按错误说明缩小操作范围或采用已支持的原生编辑。

为单镜及镜头组保留稳定名称、顺序、帧域、相机、主体、焦点、意图和锁定项。比较候选时沿用同源、同时间段和一致的显示条件。整组复制和单镜变更分别建候选，原组可作为恢复点。

## 选择真实操作入口

Camera Live 面板提供镜头表、候选载入、同帧 A/B、候选播放及恢复视口。Windows Camera Copy 面板提供检查、生成副本和打开已验证副本。精细路径、关键帧和手柄使用 Blender 原生编辑器，保存后重新读取再接续。

| 操作 | 当前入口及检查重点 |
|---|---|
| 静态机位或焦距 | `Check Static Camera Copy`。显式镜头、焦距和相机局部偏移。校验独占、动画、DOF 及共享关系，固定朝向按当前契约保留。 |
| 相邻切点 | `Check Adjacent Cut Copy`。点名左右镜头和左镜末帧，检查连续且非空的镜头区间。 |
| 骨骼目标对焦 | `Check Bone Focus Copy`。点名已有对象、骨骼与光圈，按支持的原生结构检查。 |
| 既有运镜节奏 | `Check Camera Motion Copy`。读取合格的原生两端位置曲线，在固定端点和时段内选择缓入、缓出或缓入缓出。 |
| 移焦起点 | `Check Focus Timing Copy`。点名已有焦点辅助对象、新开始帧和三处锁定帧，保留到达及外侧事件。 |
| 摄影组整体改时 | `Retime Camera Group Copy`。点名摄影 Collection、全部相关 Actions 和 markers，提供源及目标半开区间和锁定帧。 |
| 构图建议 | `Diagnose Saved Framing`。读取显式构图规格，报告逐帧问题及有限候选。存在可行建议时进入已有静态相机复制检查。 |

公共调用使用随仓库发布的 `cli_bridge.py`，由同一运行环境调用共享服务。桥接动作包含 `diagnose`、`check`、`apply`、`cancel`、`result`。按当前桥接代码与包清单构造请求，绑定脚本、源、资源和 `adapter_manifest_sha`。使用现有 `blenderctl` 的 `extension.run` 时读取其真实请求契约，避免从面板名称推导命令。

检查返回 READY 后审阅候选再提交。生成阶段输出新文件并进行独立重开验证。打开副本前核对当前 GUI 与检查时会话，保护正在进行的编辑。取消、提交和终态分别按实际回执判断。

## 构图、运动与光学复核

构图规格点名采样帧、主体网格、关注点、中心、占比、边缘留白、视线方向、轴线及例外。有限搜索需显式偏移或焦距范围和锁定项。不可满足时报告具体帧、对象、冲突条件和已搜索范围，再讨论可放宽的条件。

遮挡检查基于目标射线。透视相机使用投影中心，正交相机使用经过目标画面坐标的平行射线。允许的前景只影响目标可见性分类，同一物体继续参与相机净空与采样间穿越检查。说明包围盒、目标点、净空探针和样本间线段覆盖范围，重要路径结合连续画面复核。

选择运动时同时检查起幅、关键事件、最大动作范围和有效落幅。推拉、侧移、升降、转向、跟随和环绕可以组合。相机位置、朝向和焦距分别读回，判断主体尺度与空间关系。依据镜头目的决定进入和离开时的速度。

手持或震动使用可独立调整的原生层及明确强度、时段和恢复段。甩镜检查快速转向与清晰落点，运动模糊按实际渲染快门验证。推拉变焦联合核对相机位移、焦距与主体画面尺度。模板复用同时适配主体映射、站位、尺度、朝向和时域，检查相机、Aim 与 Path 的实际求值关系。

对焦检查实际焦点对象或骨骼、焦深及目标画面。使用能够显示 DOF、焦距动画和运动模糊的引擎观察过渡。原生属性和曲线求值用于定位问题，最后通过真实图像判断清晰范围、节奏与可读性。

## 预览、交接和恢复

探索用工作副本和快速预览。里程碑检查真实入口、代表时刻、非目标保护和持续画面。正式交付或跨入口交接持久保存，独立重开并核对所需依赖。复用未变化的有效证据，根据变更影响决定复验范围。

原速看完整镜头，定位问题窗口后放回前后镜头复看。静态构图可用同条件关键帧，运动、节奏、拉焦和接镜需要连续预览。交付可编辑工程、逐镜与连续预览、镜头表、必要代表帧及实际诊断结果。最终组接使用现有剪辑流程，并核对帧率、切点、入出点及源媒体依赖。

记录明确局改请求到可判断预览的端到端时间，包含准备、执行、输出和查看。首次恢复、依赖准备、渲染和用户等待按实际情况说明。

失败先读取作业进度、日志、终态与所属进程，确认可消费的成功步骤和保留产物。源、请求、资源或代码变化后重新检查。恢复使用新作业目录及有效检查点，保留原候选与未受影响镜头。原生手改另存后重新读取完整状态，只调整点名内容。

收尾核对任务目标、实际画面、持久文件和依赖，将已通过行为、平台及输入限制写清。关闭明确属于本次且已安全退出的 Blender 验证进程。
